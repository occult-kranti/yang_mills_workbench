# Round22 bounded presentation review

This is a presentation review, adding zero research loops. It covers the Round22 renderer/CSS, both builders, seven populated metadata entries and the Round22 test. Q2/R metadata, ten-loop build inputs and index wiring are intentionally unfinished and are not defects. No frozen producer artifact was changed. The complete-cycle builders and test were not run against the incomplete cycle.

## Actionable findings

1. **Historical Round21 navigation loses its contribution page (medium).** `dist/research-round22.js:47–51` claims the generic `home` and `contributions` routes, but renders the historical home and delegated Round21 pages without translating their links. The inherited navigation at `dist/research-round21.js:40–43` still uses `#research/contributions` and `#research/home`. Consequently, “Contributions” on the Round21 history page opens the Round22 contribution ledger; no Round21 contribution alias is supplied. This also affects the navigation on delegated Round21 loop pages. Add an explicit historical contribution alias and translate historical home/contribution links, preserving the deliberately current-return links. The existing Round20 wrapper at `dist/research-round21.js:44` demonstrates the needed distinction. The `round21-home` title also falls through the prior `afterRender` chain because the alias is unknown there (`research-round22.js:58`; `research-round21.js:57`); set its historical title explicitly. Test rendered legacy navigation, not only the forwarded route name.

2. **Interaction tests never execute the interaction code (medium test gap).** `tests/test_round22.mjs:11` supplies no document or location, and lines 40–48 only inspect strings. `ResearchRound22.afterRender` is never called. Deleting all event wiring at `dist/research-round22.js:61–63` would still satisfy the current “Chapter routing” assertions. Add a small DOM fixture that calls `afterRender`, clicks a chapter button and verifies target focus, scrolling, unchanged application hash, and the reduced-motion branch. Exercise initial calculator output plus both input/change updates, and the historical journey cleanup/delegation path. A read-only mocked-DOM probe during this review confirmed that the current code focuses the chapter, uses `instant` for reduced motion, retains `#research/journey`, initializes the readout to `0.36388` at q=0.9/gamma=2.5, and changes it to `1.1023` with the insufficiency warning at gamma=3. This is a missing regression guard, not a reproduced failure of those handlers.

3. **Builder metadata validation accepts malformed derivations and an inconsistent roadmap (low, fail-fast validation).** `build_claim_map.py:16` checks only `len(steps)>=3`, so the string `"abc"` passes as a reviewed derivation. `build_site.py:17–18` requires a list but still accepts `[{}, {}, {}]`, which becomes three `[object Object]` steps in the renderer. Require at least three nonempty strings in both builders, preferably through one shared validation function. Validate the other required prose fields as nonempty strings. At `build_site.py:27–31`, require exactly three future goals and strict `executed is False` before producing a page that says those goals are merely planned (`research-round22.js:21`). The existing test catches those two roadmap conditions later; the builder should reject the contradiction itself. The claim map's path-only future-roadmap reference is intentional under `release/protocol.md:3`, and is not a missing-content-binding defect.

4. **The gate-binding test checks a value against itself (medium test gap).** `tests/test_round22.mjs:32–38` checks that the renderer prints the `gate_sha256` already supplied by generated data. It does not hash the actual gate or compare the displayed claim, equations, scope and target verdict with the gate. Editing a generated claim while retaining its hash would evade these assertions if both asset copies were changed. Add direct comparisons with each admitted gate and SHA256 of its bytes, or narrow the advertised check at line 51 to “renders supplied gate identifiers.” The builder does validate admission and overwrite these fields from the gate (`build_site.py:15–24`), and final inventory verification provides another layer; this finding concerns the test's independent coverage and stated result.

5. **Evidence links use a mutable revision (low provenance weakness).** `dist/research-round22.js:8–9` points every proof and admission link at `blob/main/` while displaying a frozen gate hash. A later change to that path can make the link serve different bytes from the presented admission. Consider recording the published source commit in the generated data and linking evidence to that revision. This is not a claim that any current evidence bytes differ.
