**The contract wording defects pattern.** Three recurring shapes across the round, all non-blocking by the panel's rule (a phrase inside an exclusion list is never an assertion) but all avoidable:
1. *Placeholders left past the point where they should have been pinned.* AZ2's `parameters.j_max` carried the literal template text `"<declared, e.g. 3/2 and 2 with certified tail>"` into a late draft (Jung assistant-4 defect 8, flagged in this lens's `update-4.md` §3); the eventual fix — the cutoff read as polynomial degree `D in {6,8}` of the Round11 basis, where a per-link `j_max` is not even well-posed — came from the panel's contract requirement, not from filling the placeholder as written.
2. *Blocks copied wholesale from an earlier loop's template without adapting the copied field to the new loop's own model.* AZ1's `preregistration.selected_triple_alpha_units` carried the patterned-zero-selected family's `["0","0","0"]` under a `model_id` naming the uniform route-B model, whose own AX1 contract used the symbolic triple `["tau/24","tau/24","tau/24"]`; `az1-contract-review.md` reading 1 catches it as "a block that looks copied from AY2," and it binds no admitted quantity only because AZ1's report never depends on the triple's literal value. The same shape, differently, is the AY1/AY2 contracts' verbatim carry-over of "uniqueness of the AQ state" inside an exclusion list — harmless there because it names a claim to rule out, but replaced going forward ("uniqueness of any subsequential limit," `plan.json`'s second vocabulary extension) rather than silently repeated a third time.
3. *A coupling or coefficient left inferable from a dictionary sentence rather than fixed in the model block.* AZ2's contract named "coupling `tau_FG` in a declared grid" without saying which of the graph's two faces carried it (W-A, Section 1 above), so a one-face and a two-face reading were equally well supported by the frozen text; only the producer's disclosure and the skeptic's independent third-order computation resolved which model the gate would admit.

**Rule for the next round.** Before a contract freezes, any field copied or adapted from an earlier loop's template — a selected-triple block, a target block, a `gate_fields_required` list — should be checked against the new loop's own `model_id` and observable *by name*, not only for the field's bare presence; and any contract that couples more than one named finite or infinite object (more than one face, more than one boundary shell, more than one construction family) must state the coefficient or weight on each object explicitly in the model block itself, never leave it to a dictionary sentence that reads equally well two ways. This is one rule stated twice: name every source, load and coefficient before production starts, so that a producer's disclosure is confirming a fixed model rather than resolving an open one.

## 4. Recommendation for the next round's goals

`advisor/roadmap.json` ranks, in order: 1 `uniqueness`, 2 `dynamics`, 3 `whole_sequence`, 4 `second_order`, 5 `continuum`. This lens agrees with the set of five goals — nothing should be replaced, since each names a real missing premise the round's own gates identified (`ay2-gate.json` items (5), `az1-gate.json` `limitations`) — but recommends reordering two pairs, for reasons this lens's own method has applied consistently across the round.

1. **`dynamics` (promoted from rank 2 to rank 1).** Newton's rule — compute exactly what is already deducible before charging a new budget — is already satisfiable here: the missing premise is not a new mathematical object but an unexecuted application of already-admitted constants (AQ1's Nachtergaele–Sims data, `F(r)=(1+r)^-4`, `C<=224`, `||Phi||_F<=2268|tau|`, `||Phi'||_F<=1323|tau|`, all cited in `ay2-gate.json`, none re-derived) to a boundary shell whose size is already exactly known (`28N(5N+1)` extra faces at distance `N-1`, independently re-derived in this lens's own `assistant-4/padding_family_contraction.py`, matching the AY1 producers bit-for-bit at `N=2,3` and extended to `N=4`). Tesla's source/load/clock discipline is already fully named in the roadmap's own `proposed_first_loop_test` ("Apply Nachtergaele-Sims Theorem 4.1 to the padded owner-set interaction and bound the boundary contribution on `[0,T]` with `T=1` in the common clock"). It is also independent of goal 1: it compares dynamics between two already-fixed families, not uniqueness across every subsequential limit, so it does not need `uniqueness` solved first, and a positive result here would supply the one dynamical obligation among AY2's six that this round left completely untouched. This sub-round's own web search (Section 5) — "Lieb-Robinson bound boundary independence Kogut-Susskind lattice gauge theory dynamics 2026" — found no external shortcut and nothing dated 2026 addressing this exact combination, confirming the internal Nachtergaele–Sims route the roadmap already names is the only one on the table, and it is ready to run without further reading.
2. **`uniqueness` (kept at high priority, one slot down).** Agreed as the master obligation: `whole_sequence` and translation invariance both depend on some form of it, and it is the obligation every prior sub-round's roadmap discussion has treated as central. One disagreement with the `proposed_first_loop_test`: it leads with "a Dobrushin-type interdependence matrix," but this round's own source search (`update-4.md` §5) found the one concrete quantum-Dobrushin object in the literature — M32-DOB26, Bakshi–Liu–Moitra–Tang, arXiv:2510.08542 — is a *high-temperature* Gibbs-sampler mixing result with no constructed bridge to a fixed-spacing, effectively-zero-temperature ground-state statement. Leading with it risks a formulation exercise with no known route to completion — exactly the "no hypothesis without deduction" trap this lens has flagged all round. Recommend leading instead with evaluating the named, unformulated-but-existential Yarotsky/HTW constants `c_1(S)`, `c_2(S)` for the AM2 fixed point, since these are already tied to this model's own contraction proof (deducible from the frozen Hamiltonian, in Newton's sense) rather than imported from an unrelated high-temperature theorem; keep the Dobrushin lead on record as a secondary route, to be revisited only if a future paper builds the missing bridge.
3. **`whole_sequence` (kept at rank 3, dependency recorded).** Agreed with the rank, with one addition: a quantitative Cauchy estimate in `N` is exactly the kind of boundary-decay statement a completed `dynamics` loop's Lieb–Robinson tail would likely supply as a byproduct, over the same `28N(5N+1)`-face boundary shell now tracked as a function of `N`. Recommend the next round's advisor treat `whole_sequence`'s first loop as conditional on `dynamics`'s outcome — if the Duhamel bound there closes with an explicit `N`-dependence, `whole_sequence` may need extraction from it, not a fresh derivation.
4. **`continuum` (kept, promoted one slot, from rank 5 to rank 4).** Agreed this stays low: five consecutive sub-round source searches (every one of this lens's updates 1 through 5) have found no rigorous uniform-in-`a` result for a comparable strong-coupling lattice family, and nothing changed this sub-round either. It is ranked above `second_order` only because it remains, at least, a question with a real external answer to wait for and a cheap, honest check to repeat (a statement loop recording any newly audited external construction as a lead, per the roadmap's own `proposed_first_loop_test`), whereas the next item's own stated limitation removes even that payoff.
5. **`second_order` (demoted from rank 4 to rank 5, and recommended not to run as a standalone loop).** The roadmap's own text for this goal already states the reason to demote it: "a smaller constant does not change any gate field." Reducing `K_2'` (about 13417.5, 99.99% the generic AM2 remainder majorant per `ay1-gate.json` `limitations`) by an R-local second-order expansion is a real computation, but on its own it certifies nothing that is not already certified. Recommend the next round's advisor hold this goal in reserve and run it only if triggered as a genuine dependency of one of the other four — for instance, if `dynamics`'s Duhamel bound needs a sharper second-order constant to close within the cap — rather than scheduling it as a freestanding investigation.
