# Round19 advisor gate format

Status: format instruction for future accepted/limited/rejected gates. This is not a scientific gate.

Use `research/round19/advisor/a1-gate.json` for A1 and the analogous lowercase loop name for later loops. A gate may be written only after the advisor has reviewed actual executed evidence, not from status strings alone.

Required top-level fields:

```json
{
  "loop": "a1",
  "status": "accepted | limited | rejected",
  "scope": "precise narrow scope of the gate",
  "mathematical_result": "exact statement supported by the evidence",
  "remaining_open": ["..."],
  "contract": "advisor/contract-a1.json",
  "normal_optimized_counted_once": true,
  "files": {
    "advisor/contract-a1.json": "sha256..."
  }
}
```

The `files` map uses Round19-relative paths and SHA-256 hashes. It should include the actual frozen contract, both role reports, executed scientific sources, normal and optimized outputs, source manifests, optimized comparison record, and independent comparison evidence. It should not include mutable overall `feedback-log.md`, future roadmap files, or continuously amended planning ledgers. If an advisor review snapshot is needed for a gate, write a separate immutable snapshot file and include that path.

A1 remains blocked until the producer manifest repair and corrected independent comparison are ready. Specific checks required before any A1 gate:

- rerun canonical producer source in normal and optimized modes and verify semantic output hashes;
- verify producer `source-manifest.json` is generated by the canonical command or otherwise source-bound without manual post-generation mismatch;
- require revised independent comparison against `ym19-forward-a1-clipped-restrictions-v1`;
- require exact parsed `E_star` and rational coupling scale checks;
- require complete `n=2..12` and four-phase domain coverage with duplicate/missing controls;
- require independent rational reconstruction of every local bound rather than trusting producer pass booleans;
- require altered-bound, altered-role, altered-signed-word and source-hash controls.
